# Atlas Heartbeat 设计说明

## 目标

在 Atlas 上提供一个无需安装第三方依赖、可直接在浏览器中打开的互动仪表盘。它把服务器的 CPU、内存、磁盘、负载、运行时长和备份计时器状态映射成一颗会呼吸的星球，让常规状态检查具有直觉和趣味。

## 方案比较

1. **实时互动星球（采用）**：真实数据驱动颜色、呼吸速度、光环和星尘，既可玩又有长期用途；需要一个很小的本地服务。
2. **纯静态数字花园**：视觉自由度高、部署最简单，但没有真实状态，完成后用途有限。
3. **声音合成器**：把负载映射为环境音，创意强，但浏览器音频权限、远程使用和无障碍体验都更不稳定。

选择第一种。范围控制为“单机、只读、单页面、无登录”，不加入历史数据库、告警、外部账户或写操作。

## 体验设计

页面中心是一颗 Atlas 星球：

- CPU 决定呼吸和旋转速度。
- 内存决定核心光的强度。
- 磁盘占用决定外环完整度。
- 系统负载决定周围星尘的活跃程度。
- 点击或按键可发出一次纯视觉“脉冲”，不改变服务器状态。
- “静谧模式”减少动画；系统的 `prefers-reduced-motion` 设置也会自动生效。

下方状态卡显示精确数值，右侧“航行日志”把数据解释为一句人话。手机屏幕改为单列，触控区域不小于 44 像素。颜色有文字和数值作为冗余表达，不仅依赖色彩。

## 架构与边界

项目只使用 Python 3 标准库和浏览器原生能力。

- `atlas_heartbeat/metrics.py`：读取 `/proc`、磁盘容量和备份计时器；所有系统访问经小接口注入，便于真实单元测试。
- `atlas_heartbeat/server.py`：提供 `/api/pulse` JSON 和静态资源；仅允许 GET/HEAD，默认绑定 `127.0.0.1`。
- `web/state.mjs`：把原始指标规范化为 UI 状态和文字，不接触 DOM，可由 Node 测试。
- `web/app.js`：轮询 API、更新 DOM/CSS 变量、管理 Canvas 星尘和交互。
- `web/index.html` 与 `web/style.css`：语义结构、响应式布局和视觉系统。

数据流为：浏览器每 2 秒请求 `/api/pulse` → 服务采集瞬时快照 → 前端规范化 → 数值卡与视觉变量同步更新。CPU 百分比使用连续两次 `/proc/stat` 快照计算；第一帧显示为可用的初始估值，之后进入稳定采样。

## 错误处理与安全

- 单项系统数据读取失败时返回 `null` 和简短状态，不让整个 API 失败。
- 前端保留最近一次有效快照；连续失败时显示“信号暂时中断”，并以较慢频率继续重试。
- 静态文件路径在解析后必须仍位于 `web` 根目录，阻止目录穿越。
- API 不执行写操作、不读取密钥、不返回进程列表或网络连接。
- 默认仅监听回环地址；需要局域网访问时由用户显式传入 `--host`。

## 测试与验收

- Python 单元测试覆盖 CPU 差分、内存解析、指标降级、路径安全和 API 响应。
- Node 原生测试覆盖百分比钳制、健康文案和动画参数映射。
- 先写并运行失败测试，再实现最小通过代码。
- 完成后运行全部 Python 与 Node 测试，启动真实服务并检查 JSON。
- 用无头 Chrome 检查桌面和手机截图、页面错误、键盘脉冲、静谧模式以及数据刷新。

验收标准：克隆后只需 Python 3；一条命令启动；两秒内出现真实指标；断开 API 时页面仍可理解；桌面和手机均无溢出；所有自动化测试通过。
